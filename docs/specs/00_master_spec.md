## [S1] 项目背景

直线加速器驱动的 FEL 束流诊断中，纵向相空间 `(z, δ)` 是判断束流品质的核心对象。以 TDS + 谱仪为代表的诊断系统输出低分辨率观测图像；真实高分辨率纵向相空间中存在低分辨率无法清楚分辨、但物理上可推断的精细结构（压缩折叠、细脊、电流尖峰、局部能散变化等）。

本项目构建一个不依赖 elegant / Ocelot 的轻量级纵向相空间模拟函数 `f(x)`，生成严格配对的 `(H, L, P)` 数据，并训练超分辨率神经网络，验证一个核心问题：在低分辨率观测下，物理先验能否帮助网络更准确、更符合物理地恢复高分辨率纵向相空间。

### Claims

- C1: 项目 SHALL 提供不依赖 elegant / Ocelot 的纵向相空间模拟函数 `f(x)`，其输出为 `(H, L, P)` 三元组及元数据 `m`（见 `[S4]`），其中 `H` 为高分辨率真值、`L` 为低分辨率观测、`P` 为可注入网络的物理先验。
- C2: 项目 SHALL 通过受控实验回答「物理先验能否提升低分辨率超分恢复的精度与物理一致性」这一核心问题，并在最终报告中给出定量结论。
- C3（本节新增）：本项目 SHALL 采用**替代验证（Substitute Verification）**研究范式：用合成数据生成函数构造严格配对的 `(H, L, P)`，先在受控环境内验证超分神经网络的可行性，再决定是否将方法迁移到 elegant/Ocelot 高保真仿真或真实诊断数据；本项目 SHALL NOT 被理解为「替代 elegant/Ocelot 仿真」。

### 研究方法论定位

本项目**不是**用神经网络替代 elegant/Ocelot 仿真；**而是**用合成数据替代真实数据来**验证超分神经网络本身的可行性**。

**逻辑链**：
```
合成数据 (H, L, P) → 验证 SR 网络能恢复精细结构
       ↓（如果成功）
考虑迁移到真实数据：elegant/Ocelot 仿真 或真实 TDS 诊断
```

这与"先验证方法、再应用到真实场景"的经典科研路径一致：M0–M5 全在合成数据上执行；M6 出口决策（`90 [S6]`）判断是否进入下一阶段。

**关键边界**：
- 本项目产出的方法若成立，是"SR 网络能用于 FEL 诊断"的可行性证据，**不是**"SR 网络能取代诊断系统"
- 在合成数据上成功不等于在真实数据上成功——但没有合成数据上的成功，真实数据上的尝试更盲目
- 模拟函数的真实性审计表（`90 [S6]` 证据3）是迁移时的关键参考

## [S2] 研究目标与研究假设

**研究目标：** 在低分辨率观测下，公平比较三种超分增强方式并评估其性能差异：

| 方案 | 名称 | 输入 | 输出形式 |
|---|---|---|---|
| A | 无先验（baseline） | `L` | `Ĥ = NonNeg(L_up + G0(L))` |
| B | 图像先验 + 残差 | `L, P2` | `Ĥ = NonNeg(P2 + G1(L, P2))` |
| C | 参数先验 + FiLM | `L, c_low + c_mid` | `Ĥ = NonNeg(L_up + G2(L | c_prior))` |

**记号约定**：
- 网络的实际输入是 `L` 上采样到 `H` 分辨率后的 `256×256` 图像，记为 `L_up`；上表中 `G0(L)`、`G1(L, P2)`、`G2(L | c_prior)` 一律满足 `G(·) ≡ G(L_up)`（实现见 `50`）。
- 总强度归一化后总强度参数 `A` 退化，方案 C 的输入参数集合为 `c_prior := (c_low \ {A}) ∪ c_mid = {σ_z, n, η, b_0, a_1, α, a_2, β}`（见 `[S4]` 与 `40` D11）。

**研究假设：** 在低分辨率图像只能看到大尺度结构、而高分辨率图像包含可推断精细结构的前提下，物理先验可以显著降低超分辨率逆问题的不确定性，并提高精细结构恢复的物理一致性。

### Claims

- C1: 主实验 SHALL 对方案 A / B / C 使用相同数据集、相同训练目标（空域-频域混合损失，见 `60`）、相同主干网络与相同训练配置进行公平对比。
- C2: 最终结论 SHALL 明确回答研究假设是否成立，并给出先验增益（`M_A - M_B`、`M_A - M_C`）的定量数值。

## [S3] 项目范围

### 3.1 本项目包含

1. 纵向相空间模拟函数 `f(x)`：高分辨率真值 `H` 生成、低分辨率观测 `L` 生成、物理先验 `P` 生成；
2. 三种超分网络：无先验（A）、图像先验 + 残差（B）、参数先验 + FiLM（C）；
3. 图像质量评估与物理一致性评估；
4. 先验增益分析与消融实验；
5. 最终研究报告。

### 3.2 本项目暂不包含（非目标）

1. 完整 elegant / Ocelot 仿真；
2. 六维相空间完整建模；
3. 真实探测器硬件数据采集；
4. 横向相空间超分；
5. 在线加速器控制系统接入；
6. GAN / Diffusion / Normalizing Flow 等生成式超分模型（第一版，除非单独立项）；
7. 估计先验 `ĉ`（第一版只预留接口，不实现）；
8. 物理损失参与训练（第一版；物理指标只在评估阶段使用）。

### Claims

- C1: 本项目数据生成 SHALL NOT 依赖 elegant 或 Ocelot。
- C2: 第一版实验 SHALL 仅包含方案 A / B / C 三种确定性残差超分网络，不包含生成式模型。

## [S3.5] 主指标语义对齐原则（测量哲学，2026-08-26 新增）

本节定义"主指标/判据测什么"的通用原则，防止"测量工具与测量目标错配"（典型案例：本项目主指标掩膜主要选中 β 折叠而非 c_high 精细结构——能量对齐 ≠ 语义对齐）。任何含"指标/判据/评估"的研究模块（`70`/`80`/`90`）SHALL 遵循本节原则。

### 3.5.1 四项原则

1. **直接因果原则**：主指标 SHOULD 直接测量研究问题形式化的物理量，而非"最容易计算的代理量"。当代理量不可避免时（如计算不可承受、直接因果不可得），SHALL 显式说明"为何用代理"与"代理的已知偏差"。
2. **差分/敏感度优先原则**：任何"基于静态量（如某类源的能量/形态）"的判据 SHOULD 优先改为"基于差分/敏感度"（如 H − H_源移除版）。静态量是混合源的混合表征；差分量是目标源的直接提取。
3. **成分分解强制披露原则**：任何"基于某类源能量/特征"的判据，报告 MUST 同步给出"源成分分解"（如目标源占比 / 邻近源占比 / 其余占比），让读者能评估主指标"测的是不是它声称测的"。分解阈值（如目标源占比 < 30%）触发"判据可能失真"警告。
4. **先验独立性可量化校验原则**：任何"先验 X 不暴露信息 Y"的声称，报告 MUST 给出"先验 X 携带 Y 信息的量化占比"（如先验泄漏指数 Π_leak）。字面校验（参数级不变）≠ 物理性校验（能量级不泄漏）。

### 3.5.2 适用与例外

- 适用：主评估指标（`70` [S7.1]）、门禁判据（`80` [S9] G0–G4）、一票否决判定（`70` [S4]）、任何"测什么"与"声称测什么"可能错配的指标。
- 例外：代理量在"直接因果不可得 / 计算不可承受"时可用，但 MUST 披露已知偏差；成分分解在"源不可分离"时退化为"已知源占比 + 未知残差"。

### Claims

- C1: 主指标/判据构造 SHALL 遵循直接因果、差分/敏感度优先、成分分解强制披露、先验独立可量化四项原则；代理量 SHALL 披露偏差。
- C2: 本节原则 SHALL 约束 `70`/`80`/`90` 的指标与判据设计，与本文件其余条款冲突时按本节优先。

## [S4] 核心符号定义

| 符号 | 定义 | 约定 |
|---|---|---|
| `(z, δ)` | 纵向相空间坐标：`z` 为纵向位置或相对时间，`δ` 为相对能量偏差 | 归一化 `z, δ ∈ [-1, 1]` |
| `x` | 自变量 `x = (c, d)` | — |
| `c` | 内容参数 `c = (c_low, c_mid, c_high)` | — |
| `c_low` | 低分辨率可见的大尺度参数 `{A, σ_z, n, η, b_0, a_1, α}` | 在 `L` 中通常可辨识 |
| `c_mid` | 中阶参数 `{a_2, β}`：二阶弯曲与主折叠 | 部分可见或可推断 |
| `c_high` | 高分辨率精细参数 `{a_3, γ, b_1}`：三阶 S 形、精细卷曲、局部厚度变化 | 在 `L` 中不可清楚分辨 |
| `c_prior` | 方案 C 的条件参数输入：`c_prior := (c_low \ {A}) ∪ c_mid = {σ_z, n, η, b_0, a_1, α, a_2, β}` | 总强度归一化后 `A` 退化，不含 `A`（见 `40` D11）；不含 `c_high` |
| `d` | 退化参数 `{r, σ_K, ρ_K, noise model, σ_n}` | 见 30 |
| `H` | 高分辨率纵向相空间真值图像，`H_ij ≥ 0`，默认 `256×256` | 由 `f_beam(c)` 生成 |
| `L` | 低分辨率诊断观测图像，默认 `64×64` | 由 `H` 经 `f_deg(H; d)` 正向退化得到 |
| `P` | 可注入网络的物理先验（默认中阶图像先验 `P2`，`256×256`） | 由 `f_prior(c)` 生成，`P ≠ H` |
| `S(δ)` | 能谱剖面（`p(z, δ)` 对 `z` 的边缘分布） | 与先验 `P` 区分，避免符号重载 |
| `λ_w` | Level 2 特征波长参数（见 `20` [S8]） | 与损失权重 `λ`（见 `60` [S2]）区分，避免符号重载 |
| `M` | 误差类评估指标（越小越好）；`M_X` 表示方案 X 在测试集上的指标值，先验增益定义为 `M_A − M_B`、`M_A − M_C` | 定义见 `10`，指标明细见 `70` |
| `m` | 物理标签与元数据：`Q, μ_z, μ_δ, σ_z, σ_δ, C_zδ, h_eff, ε_z, I_peak, I(z), S(δ), Level, c`（`Q` 为束团电荷量，`μ_z`、`μ_δ` 为 `z`、`δ` 的均值位置） | 由 `f_beam` 一并输出 |

### Claims

- C1: 全 spec 集中 `H, L, P, c, d, m` 的定义 SHALL 以本文件为准，任何子 Spec 不得重新定义或与之冲突。
- C2: 坐标归一化 `z, δ ∈ [-1, 1]` 为全局约定；`L` 与 `H` 必须覆盖相同物理坐标范围，仅像素尺寸不同。

## [S6] 全局约束

1. **术语统一**：所有符号定义以 `00` 为唯一裁定来源。
2. **物理一致性**：`H ≥ 0`；总强度守恒或归一化稳定；`L` 由同一 `H` 正向退化；`P ≠ H`。
3. **先验不泄露**：默认先验不得使用 `H`，不得包含 `c_high`；Oracle 信息只用于上限分析。
4. **三方案公平**：相同数据、相同损失、相同主干、相同训练配置、相同评估指标。
5. **第一版训练不使用物理损失**：训练仅使用重建损失（空域 + 频域，定义见 `60`），不使用任何注入物理知识的损失项；物理指标在评估阶段强制保留，且物理指标优先级高于图像指标。
6. **精细结构规则**：精细结构必须由参数决定、与低频结构相关、在 `H` 中可稳定分辨、在 `L` 中不可清楚分辨。
7. **版本受控**：修改任何 Spec 前必须先记录到 `99_change_log.md`；冻结 Spec 在实现阶段不得修改。
8. **可复现**：随机种子、配置、数据版本、Spec 版本、代码版本均须记录；其中代码版本 SHALL 为对应的 git commit hash，登记于 `config.yaml` 的 `code_version` 字段（与 `80` [S12] C2 配套）。**版本对账规范（2026-08-26 P0 修订，N4）**：`code_version` SHALL 登记 **40 位完整** git commit hash，7 位短 hash 仅可用于展示，任何持久化载体（manifest、config.yaml、summary.json、训练日志）SHALL 使用完整 hash；`spec_version` SHALL 采用 `<冻结版本>+<最新 99 批次标识>` 形式（如 `v1.0+2026-08-26`），其语义为"冻结版本文本 + 截至该批次的全部已批准变更"，载体写入的 `spec_version` SHALL 与生成时刻 `99` change log 的最新已批准批次一致。

### Claims

- C1: 任何子 Spec SHALL NOT 违反本节的全局约束；子 Spec 与 `00` 冲突时，以 `00` 为准。

## [S9] 变更规则

1. **先记录，后修改**：修改任何 Spec 文件前，必须先在该文件的变更记录（`99_change_log.md`）中创建 `Proposed` 条目，批准后改为 `Approved` 再修改；
2. **每次只修改一个模块**：一次迭代只改一个 Spec 文档；
3. **每次迭代必须有验收结果**：修改后必须给出对应验收证据；
4. **版本升级必须同步**：Spec 版本升级须同步更新 `99` 的版本历史表；
5. **禁止直接覆盖**：不允许不记录变更直接修改 Spec 文件；
6. **重大需求变更**：废弃旧 spec，按 write-spec 流程产出新 spec（旧文档保留作历史参考）。
7. **普通变更包含执行方案调整**：执行阶段（任何里程碑）发现的标定采用值、阈值、详细实现细节等调整，只要不触动不可变核心（[S10] 10.1），按 `99` [S5] 流程增量修订，**无需立新 spec**。这是研究方法细节在执行中的正常演化；规则 6 的"重大需求变更"是研究方向/不可变核心变了，二者形成对照。预注册阈值的修订（按 `90` [S6] C5 的"20% 占位值允许执行前一次性修订"条款）属于本类。

### Claims

- C1: 任何 Spec 文件被修改前 SHALL 在 `99_change_log.md` 中存在对应的 `Proposed` 记录。
- C2: 冻结后的 Spec（`00`-`90`）SHALL NOT 在实现阶段被修改；实现中的偏差 SHALL 记录到任务报告与 `99`。
- C3: 执行阶段的标定采用值、阈值、详细实现细节等调整 SHALL 按 [S9] 规则 7 + `99` [S5] 流程增量修订；触动不可变核心（[S10] 10.1）方走重大需求变更（[S9] 规则 6）。

## [S10] 不可变核心与可修改细节

本节划分 Spec 集中不可变的核心与可修改的方法细节，为「一次变更是否属于重大变更」提供机械判据。不可变核心在冻结后 SHALL NOT 被修改；确需修改时构成「重大需求变更」，走 [S9] 规则 6 的流程。

### 10.1 不可变核心（冻结后不得修改）

| 类别 | 条款（claim 引用） |
|---|---|
| 研究问题与假设 | `00` [S1] C2；`00` [S2] 研究目标表与假设、C2；`10` [S1] C1–C3、[S2] C1 |
| 三方案对比框架 | `10` [S3] C1–C4；`40` [S8] C1–C4、[S9] C3（先验不含 `c_high`）；`00` [S3] C2 |
| 公平性约束 | `00` [S6] 约束 4；`10` [S6] C1–C5；`40` [S9] C5–C7；`60` [S11] C1–C4；`70` [S1] C2 |
| 数据契约 | `00` [S4] C1–C2；`20` [S2] C1–C3、[S9] C1–C10（参数范围与掩膜 W1–W8）；`30` [S6] C8（SNR_hf 判据）、[S12] C1（256→64，r=4）；`60` [S8] C1–C4（划分协议） |
| 评估判据与预注册阈值 | `10` [S2] C2；`70` [S4] C4–C6（τ=5%、触发率 20%）、[S7] C1–C5（主/次指标、Wilcoxon、bootstrap CI、三分类）；`60` [S2] C3（λ 冻结）；`90` [S6] C1–C5（出口矩阵预注册）。**注（批次十四修订）**：预注册阈值分两类——**判据本体类**（τ=5%、触发率 20%、λ=1.0、主/次指标）冻结，修改须走重大需求变更（[S9] 规则 6）；**执行参数类**（如 `90` [S6] C5 的 20% OOD 占位值、`80` G0(b) 的 ρ≥0.1、扩集上限、最小 CI 宽度、MDE）的修订属普通变更（按 [S9] 规则 7），不触动不可变核心 |
| 总目标不变 | `00` [S7] C4；`80` [S9] C1（含三方案框架与公平性四要素） |

### 10.2 可修改的方法细节（走 `99` [S5] 普通变更流程，须同步所有引用文档并保持三方案一致）

- 主干结构数值：`50` [S7] 通道宽度（标准 48/代理 24）、残差块数、下采样级数；FiLM 注入位置（`50` [S10] C5）；
- 训练超参数：`60` [S9]–[S10] 学习率、weight decay、batch size、步数预算、patience、种子数（三方案必须一致）；
- 标定采用值：`30` [S12] σ_K/σ_n、`40` [S5] σ_smooth（协议不变、取值可调，登记于 `config.yaml` 与 `99`）；τ 固定 0.05（预注册阈值，见 `70` [S4] C5）；
- 复杂度升级路线 Level 2/3（`10` [S8]、`20` [S8]，仅限里程碑边界）；
- 评估实现细节：`70` [S5] 滤波器核尺度等（预注册值不变）；
- 报告数值与图表（`90` 的结构与模板固定，数值随结果）。

### 10.3 判定与治理规则

1. 任何触及不可变核心任一条款的变更即「重大需求变更」，唯一路径为 [S9] 规则 6：发起 → `99` Proposed → 用户批准 → 旧 spec 标记 Superseded → 按 write-spec 流程产出新 spec → 重新审查并冻结。
2. 新 spec SHALL 默认继承数据契约与公平性约束，除非其显式声明为新的研究问题。
3. 可修改细节的变更走 `99` [S5] 流程，SHALL 同步更新所有引用文档。
4. 冻结后**不**触动不可变核心的普通变更流程（[S9] 规则 7 + `99` [S5]）仍可适用；唯一触动不可变核心（[S10] 10.1）的修改路径才是重大需求变更（[S9] 规则 6）。这是阶段性冻结模式与一次冻结模式的本质区别。

### Claims

- C1: 不可变核心表所列条款在冻结后 SHALL NOT 被修改；触及任一条款的变更 SHALL 判定为「重大需求变更」并执行 [S9] 规则 6 流程。
- C2: 可修改方法细节的变更 SHALL 遵循 `99` [S5] 流程，并同步更新所有引用文档、保持三方案一致。
- C3: Spec 集冻结后，普通变更流程 SHALL NOT 适用；唯一修改路径为重大需求变更流程。
- C4: 新 spec SHALL 默认继承数据契约与公平性约束，除非显式声明为新的研究问题。

## [S14] 咨询协议

本节定义 Agent 遇到设计/判断疑问时的三级升级机制。三级按优先级使用：低级别不通过再升到高级别。**默认 Agent 尽量在低级别自主解决**。

### 14.1 三级升级机制

#### 第一级：自主解决（默认路径）

Agent 优先在本会话内自主解决：
1. **重读 spec**：查阅 `00`–`99` + `README` + `CONTRIBUTING`，定位相关章节与 Claims
2. **跑跨文档一致性检查**：`python scripts/check_spec_consistency.py`——可能发现矛盾或孤立引用
3. **跑环境检查**：`python scripts/check_env.py`——可能因环境差异导致异常
4. **按失败路径决策规则（80 附录 A）选路径**：多个失败路径时按 5 级优先级
5. **更新 progress.md**：记录自主决策与依据

#### 第二级：平台模型升级咨询

仅当第一级无法解决时触发：
- **多文档综合分析**（如：不可变核心 vs 普通变更的判定、跨文档一致性的复杂矛盾）
- **文献解读**（如：wang2026 论文具体段落的精读与扩展应用）
- **代码设计权衡**（如：神经网络架构选择、损失函数形式、超参数范围）
- **统计判定**（如：CI 含零 + 诊断不确定时如何选扩集 vs 扩种子）

咨询方式（按场景）：
- **本会话内切到更强大的模型**（如 primary / qwen3.8 max）
- **启动独立子 agent**（如 `Agent` 工具，subagent_type=plan 或 coder）做专项调研
- **WebSearch / FetchURL** 查阅外部资源（如 arxiv 论文、文档）

**强制要求**：每次第二级咨询 SHALL 写一段"咨询记录"到阶段报告附录或 `99`，记录：
- 疑问内容
- 咨询方式（哪个模型 / 哪个子 agent / 哪个外部资源）
- 得到的判断
- 决策依据

#### 第三级：用户介入

仅当以下情况触发（与 `00 [S9] 规则 6` 重大需求变更 / R2 全局上限耗尽 / M6 出口决策对齐，批次二十笔误修正）：

- 触动 `00 [S10]` 不可变核心（任一条款）
- R2 全局上限 1 次耗尽后的二次修复
- M6 出口决策（是否进入下一阶段）
- 任何触动研究方向的决策

用户介入流程：`99` 登记 Proposed → 用户批准 → 执行。

### 14.2 预授权变更类（批次二十一用户拍板）

无人值守环境无审批者，以下变更允许 agent **自批准**（在 `99` 登记并注明"预授权类"），无需用户介入：

1. **标定采用值登记**（σ_K/σ_n/σ_smooth 标定后按协议登记，`30` [S12] / `40` [S5]）；
2. **引用/笔误修正**（不改语义的文字修正，如符号引用、章节号、笔误）；
3. **模板默认值填充**（config.yaml.template 占位值落地为具体值）；
4. **不改判据本体的阈值落地**（执行参数类预注册值的具体化，见 [S10] 10.1 注释）。

仍强制升级用户的：触动不可变核心、研究方向、R2 二次、M6 出口。

### 14.3 二级咨询默认可用 + 降级条款

**默认可用声明（批次二十三用户拍板）**：咨询 agent（更强模型 / 子 agent / WebSearch）掉线可能性极低，SHALL 视为默认可用。需要咨询时，Agent SHALL **直接发起咨询**（按 [S14.4] 提供自包含背景 + 详细问题），SHALL NOT 因担心通道不可用而推迟咨询或降级为自主拍板。

降级条款（仅在咨询通道**确实**不可用时触发）：

若执行环境不具备二级咨询手段（更强模型 / 子 agent / WebSearch 均不可用）：

- Agent SHALL 选择**对三方案公平性影响最小的保守选项**；
- SHALL 按 [S14.2] 疑问标准格式记录完整推理；
- 将该决策**置为待复核**（登记 `99`），待人工环境恢复后复核。

## [S15] 流程漏洞审计方法论（研究治理基础设施，2026-08-26 新增）

本节定义跨阶段、跨项目的研究治理基础设施：每个阶段完成时系统性扫描"技术实现假设 vs 实际数据/实现"型裂缝，防止（本项目 M3 已暴露的）"冻结 spec 隐含假设在数据层不成立"类问题重复发生。

### 15.1 审计触发

1. **每阶段完成时**（M1–M6）：主 agent SHALL 在写 stage_report 前完成一次流程漏洞审计；
2. **发现"假设 vs 实际"裂缝时**：主 agent SHALL 在提交修复前先扩展审计清单；
3. **收到 spec 修订提案时**（99 Proposed）：主 agent SHALL 在签收前做该条款的"假设 vs 实际"核查。

### 15.2 审计清单（基线四类）

1. **隐藏假设 vs 实际数据/实现对称性**——对每个 spec 公式/默认值，问"什么数据/实现条件下此假设成立"，实测验证；
2. **判据/指标操作化校验**——对每个主判据问"该判据的物理含义与 spec 文字是否严格对齐"，做能量级 vs 参数级分解（依 [S3.5]）；
3. **跨模块契约核查**——对每个"模块 A 输出 → 模块 B 输入"链条问"空间/单位/边界是否一致"，做端到端追踪；
4. **失败路径预注册**——对每个门禁问"失败时有什么出路"，列失败路径与升级触发；
5. **预注册纪律对账**——对每个预注册值问"实际载体（code/data/spec/version）是否严格一致"，跑对账脚本。

### 15.3 审计方法

- 工具：复用 Qwen 深度审查模板（含 `results/consultation/` 参考实现），形成每阶段报告的"流程漏洞"附录；
- 时间预算：30–60 分钟（不阻塞当前阶段交付）；
- 产出：`99` 登记（新 OQ）+ 新 spec 修订建议（按 P0/P1/P2/P3 优先级）；
- 不阻塞当前阶段（除非发现 P0 级阻断）；
- 审计清单随项目演化——每次发现新裂缝类型即扩展清单（本节的基线清单是最小集）。

### Claims

- C1: Agent SHALL 在每阶段完成时执行流程漏洞审计（[S15.2] 基线清单），审计产出登记 `99` 并写入阶段报告附录。
- C2: 审计发现 P0 级阻断时 SHALL 先处置再推进；其余按 P1/P2/P3 优先级排入后续修订。
- C3: 本节审计方法论 SHALL 随项目演化持续扩展清单；新裂缝类型 SHALL 在发现时补入清单。

## Decisions

### D1: 多文档渐进披露
**Chosen:** 1 个 Master Spec + 10 个子文档（`00`-`99`），按需精读。
**Rationale:** 单个超长 Spec 会造成上下文过载；渐进披露更适合 Agent 长程执行、局部修改与多 Agent 分工。
**Rejected:**
- 单一 monolithic spec 文件 — 文档过长、Agent 不易阅读、改一处需重写全文。

### D2: 十位留空编号
**Chosen:** `00 / 10 / 20 / ... / 99` 十位留空编号（风格 B）。
**Rationale:** 便于后续插入子模块（如 `21`、`22`）而不需重命名后续文件；十位数表示大模块、个位数表示子模块。
**Rejected:**
- 紧凑编号 `00 / 01 / 02 / ... / 09` — 扩展时需重排后续所有编号；
- 无编号纯文件名 — 文件排序不稳定，Agent 不知道先读哪个。

### D3: 变更与决策记录集中在 `99_change_log.md`
**Chosen:** 版本历史、变更明细、未决问题统一维护在 `99_change_log.md`，各子 Spec 的 `## Decisions` 节只记录该模块的头脑风暴期决策。
**Rationale:** 对话中确定的 spec 集结构即为此设计；避免每个子 Spec 额外维护独立决策日志文件带来的维护负担与编号冲突。
**Rejected:**
- 每个子 Spec 各带一个独立 `<slug>.decisions.md` 决策日志 — 与 `00`-`99` 结构重叠，决策编号难以统一。
