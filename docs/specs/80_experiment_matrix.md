# 80_experiment_matrix.md Spec

- 版本: v0.1（草案，待审查）

## 文档目的

本文件是项目的执行蓝图：将 `20`（物理生成）、`30`（退化）、`40`（先验）、`50`（网络）、`60`（训练）、`70`（评估）组装为具体的实验任务，定义实验阶段划分与优先级、各实验的数据集配置（规模、物理等级、退化等级）、参与对比的模型（A / B / C）、核心汇报指标、结果记录与交付规范。本文件只规定「跑什么实验、用什么数据、对比什么模型、记录什么结果」，不定义网络结构、训练损失与评估指标的计算式（分别由 `50`、`60`、`70` 定义）。

---

## [S1] 职责与范围

本文件负责实验的组织与执行契约。各阶段目标、数据集配置、模型集合、汇报指标与结果交付规范均在本文件定义；其余模块的细节以对应子 Spec 为准。

### Claims

- C1: 本文件 SHALL 定义实验阶段划分（Phase 1–4）、各阶段目标与优先级。
- C2: 本文件 SHALL 定义实验矩阵 EXP-01 至 EXP-08 的数据集配置、模型集合与执行方式。
- C3: 本文件 SHALL 定义核心汇报指标与结果记录、交付规范。
- C4: 本文件 SHALL NOT 定义网络结构（`50`）、训练损失与优化协议（`60`）、评估指标计算式（`70`）与物理生成细节（`20`）。

---

## [S2] 实验阶段划分

实验划分为四个阶段，按最小可行性验证（MVP）到进阶泛化测试组织。**Phase 1 与 Phase 2 是第一版必须完成的核心（MVP）**；Phase 3 与 Phase 4 为进阶研究，不阻塞第一版交付。

| 阶段 | 名称 | 核心目标 | 优先级 |
|---|---|---|---|
| **Phase 1** | Sanity Check（管线验证） | 跑通数据生成、网络前向/反向、Loss 下降，验证代码无 Bug | **最高（Must）** |
| **Phase 2** | Main Experiment（主实验） | 在标准分布下公平对比 A / B / C，回答「先验是否有效且物理正确」 | **最高（Must）** |
| **Phase 3** | Robustness（鲁棒性消融） | 测试不同退化强度（强模糊 / 高噪声）下先验的抗干扰能力 | 中（Should） |
| **Phase 4** | OOD Generalization（外推泛化） | 训练在 Level 1，测试在 Level 2（含 CSR/wake）或极端参数，测泛化 | 低（Could） |

### Claims

- C1: 实验 SHALL 划分为四个阶段：Phase 1 Sanity Check、Phase 2 Main Experiment、Phase 3 Robustness、Phase 4 OOD Generalization。
- C2: 第一版（MVP）SHALL 强制完成 Phase 1 与 Phase 2；Phase 3 为 Should 级、Phase 4 为 Could 级扩展。
- C3: Phase 2 主实验 SHALL NOT 在 Phase 1 管线验证通过（Loss 正常下降、输出非负且形状正确）之前启动。

### 代理实验协议

代理尺度实验限定为 ≤5,000 训练样本、≤20,000 训练步数，用途仅限超参数的选择（损失形式与默认权重由 `60` 定义；$\lambda$ 冻结为 1.0，不做代理选择，见 `60` [S2] C3）。超参数一经选定 SHALL 冻结，每个冻结配置 SHALL 只定稿一次（含其种子集，全量每方案恰 2 种子），避免以全量运行反复调参带来的选择偏差。

**GPU 使用质量登记表（两阶段）。**
- 本项目为本地服务器（实测硬件 2026-08-25）：
  - **GPU**：2× Quadro RTX 6000（Turing 架构，Compute Capability 7.5），单卡 24GB 显存，NVLink 2×25.78 GB/s，PCIe Gen1 ×16
  - **CPU**：2× Intel Xeon Platinum 8280（共 112 线程，2.70 GHz）
  - **内存**：991 GiB（可用 971 GiB）
  - **磁盘**：/home 22T（可用 20T，NVMe ~2.9 GB/s）
- GPU 时间不计费；监控重点为 **GPU 利用率与多卡并行策略**，不是预算上限。
- 显存限制：单卡 24GB → batch size 上限约 8–16（见 `60` [S9]）；Turing 7.5 支持 fp16 但不支持 bf16（见 `60` [S9] precision 说明）。
- **NVLink 澄清**：NVLink 提供 GPU 间高速互连（梯度 AllReduce、数据并行），**不合并显存**——每卡显存物理独立（24GB），batch 上限仍受单卡限制；两卡用于吞吐 2×（DDP 数据并行），非显存池化。跨卡访问（P2P）速度 ~25.78 GB/s，远低于本卡 HBM2（~672 GB/s），故 SHALL NOT 将激活值跨卡放置。
- PCIe Gen1 较慢：数据加载可能成为瓶颈；因 CPU 112 线程 + 内存 1TB，建议 `num_workers` 取 16–32 以缓解（见 `60` [S7]）。
- EXP-01 前：短程剖析方案预注册——标准配置（C0=48）跑 1,000 步，测量 GPU 利用率（nvidia-smi）、显存占用、每步墙钟、6 次训练总耗时估算（仅作时间预期）。
- EXP-02 前：用标准配置短程剖析（约 1,000 步）实测 GPU 利用率与 step_time，重新估算总耗时，登记 `config.yaml` 与 `99`。
- **EXP-01 完成后（批次十四用户拍板）**：用 EXP-01a（5,000 步调试训练）的实测 step_time / 显存占用 / GPU 利用率**重算 EXP-02 时间估算**并登记 `config.yaml` 与 `99`；若估算总耗时显著超预期（如 6 次训练 > 2× 登记表预期），SHALL 按 99 普通变更**提前调整**（降 batch / 降步数上限），SHALL NOT 等到 EXP-02 前才发现。
- GPU 使用质量登记表监控以下指标：
  - **GPU 利用率分档阈值**（按配置差异化，标准 / 代理 / Debug 分别设定）：
    | 配置 | C₀ | batch | 阈值 |
    |---|---|---|---|
    | 标准 | 48 | ≥16 | ≥80% |
    | 代理 | 24 | 8 | ≥70% |
    | Debug | 24/48 | 4–8 | ≥60% |
    每 100 步记录，写入 `results/<EXP>/gpu_utils.log`。
  - **显存使用**：< 90%（防 OOM）；同上记录于 `gpu_memory.log`
  - **多卡并行**：6 次训练 ≤3 批次（每批 2 训练并发，2 卡并行）
  - **调度顺序（批次十九用户拍板）**：按方案顺序（A→B→C）× 种子（0→1）分 3 批次——批次1: A_seed0 + B_seed0；批次2: A_seed1 + B_seed1；批次3: C_seed0 + C_seed1。理由：A、B 在批次 1–2 完成 → EXP-07（只依赖 B）可尽早开始；C 最后。
  - **计算完整性**：所有计算层 `.cuda()` 上，禁止 CPU 瓶颈运算（如 FFT 显式在 CPU）；代码 self-check
- 触发：GPU 利用率持续 <对应档位阈值（按上表；滑动窗口 100 步中 >50% 步 < 阈值，且超总训练步数 20%）SHALL 触发以下检查：
  - 数据加载是否成瓶颈？→ 增加 `num_workers`
  - batch 是否过小？→ 评估显存余量后调整
  - 是否混用 CPU 操作？→ 代码审查
  - 如无法提升：登记 `99`，**不视为失败**，但需记录原因与处理过程

#### 硬件配置降级策略（GPU 数量 fallback）

| 配置 | 假设 | fallback（如果硬件不满足）|
|---|---|---|
| **标准配置** | 2× Quadro RTX 6000 24GB/NVLink | 1× 卡：实验仍可执行，但 6 次训练 ≤ 6 批次（每批 1 训练）；并行度降 50%，总时间约 2× |
| **代理变体** | 2× 卡（任一可用）| 1× 卡：可行，单批单训练 |
| **Debug** | 单卡 | 必须有单卡；否则换 GPU |

降级原则：
- **降级不影响三方案公平**——A/B/C 仍共享相同硬件配置
- **降级不修改 spec**——这是环境差异，不是研究问题
- **降级需登记 `99`**——记录实际硬件与原假设差异
- **降级不重置算 λ 等预注册参数**——这些是研究契约，不随硬件变

判定：6 次训练总耗时超 2× 估算 → 登记 `99`，按 G1/G2 失败路径处理（[S9]）。


成本控制不等同于"降配"；GPU 利用率不足的处理流程见本节。

#### Claims

- C4: 代理尺度实验 SHALL 满足训练样本 ≤5,000、训练步数 ≤20,000，且用途 SHALL 仅限超参数的选择（$\lambda$ 冻结为 1.0，不做代理选择，见 `60` [S2] C3）。
- C5: 超参数一经代理尺度选定 SHALL 冻结（$\lambda$ 冻结为 1.0，见 `60` [S2] C3）；每个冻结配置 SHALL 只定稿一次（含其种子集，全量每方案恰 2 种子）；实现级失败重跑不视为配置变更（重跑授权见 [S11] R2）；SHALL NOT 以重复全量运行迭代超参数；统计判定所需的重跑（扩种子或扩测试集）仅允许发生在 [S9] G2 失败路径中，且 SHALL 记录于 `99`。
- C6: GPU 使用质量 SHALL 按本节「GPU 使用质量登记表（两阶段）」管理：短程剖析方案于 EXP-01 前预注册，具体 GPU 利用率与 step_time 于 EXP-02 前以标准配置短程剖析（约 1,000 步）实测后登记 `config.yaml` 与 `99`；GPU 利用率持续 <80% SHALL 触发检查流程（num_workers / batch / 代码审查），SHALL 登记 `99`，不触发"算力降配"。

## [S4] Phase 1: Sanity Check（管线验证）

Phase 1 验证数据生成、网络前向/反向与训练循环无 Bug。EXP-01 只要求 Loss 正常下降与输出形状正确，不要求最终指标达到目标水平。

**EXP-01: 快速调试**

- 数据集：2,000 Train / 500 Val / 500 Test（Level 1 物理，标准退化 D2）。
- 模型：A（无先验）、B（图像先验）、C（参数先验）。
- 训练：5,000 steps，Batch size 8。
- 目标：三个模型 Loss 均能正常下降，输出 $\hat{H}$ 非负且形状正确（`256×256`）。

**EXP-01 子任务分解**：EXP-01 为复合实验，按依赖顺序包含以下子任务：

| 子任务 | 内容 | 数据/配置 | 产出 | 承接 |
|---|---|---|---|---|
| EXP-01a | A/B/C sanity 训练 | Level 1 · D2 · 初始参数，5,000 steps | 收敛曲线、sanity 指标 | `60` AC8、G1(a) |
| EXP-01b | 方案 A 双退化档训练 | Level D1 与 D2 各一次（初始参数） | 两档退化下的 A 模型 | `30` [S12] C3 σ_K 标定（$R_E$ 比率门） |
| EXP-01c | σ_n 标定 | 尾部 SNR 2–5 判据（`30` [S12]） | σ_n 采用值 | `30` [S12] |
| EXP-01d | σ_smooth 扫描 | 3–5 个候选值（`40` [S5]），在 EXP-01a 验证集评估 | σ_smooth 采用值 | `40` [S5] 能量预算 $[0.5, 0.95]$、`40` [S12] AC14 |

执行顺序：EXP-01a → EXP-01b/01c（σ_K/σ_n）→ EXP-01d（σ_smooth，依赖 $L_{\text{up}}$ 与 σ_n）。

EXP-01c/01d 复用 EXP-01a 的数据与权重，不启动新训练（仅数据采样与评估）。

标定值生效规则：EXP-01 本身以初始参数值运行；标定采用值自 EXP-02 起统一采用（`30` [S12] C5）；G1 在初始值数据上评估。

预算口径：每个子任务独立适用代理尺度预算（≤5,000 样本、≤20,000 步）；EXP-01 各子任务的运行次数与配置 SHALL 在结果目录（[S8]）中登记。

### Claims

- C1: EXP-01 数据集 SHALL 为 2,000 Train / 500 Val / 500 Test，物理等级 Level 1、退化等级 D2。
- C2: EXP-01 SHALL 分别训练 A / B / C 三个模型，训练 5,000 steps、batch size 8。
- C3: EXP-01 通过标准 SHALL 为：A / B / C 的 Loss 均正常下降，且输出 $\hat{H} \ge 0$、形状为 `256×256`；不要求最终指标达到目标水平。
- C4: EXP-01 SHALL 按 `30` [S12] 标定退化参数（σ_K/σ_n），标定采用值记录于 `config.yaml` 并在 `99` 登记。
- C5: EXP-01 SHALL 按本节子任务表与执行顺序进行；子任务 SHALL NOT 被跳过或擅自合并。
- C6: 每个标定项完成后，其采用值 SHALL 登记于 `config.yaml` 与 `99`；标定失败时按各文档定义的出口路径处理（`30` [S12]、`40` [S5]）。

## [S5] Phase 2: Main Experiment（主实验，In-Distribution）

Phase 2 在标准分布（Level 1 物理、退化 D2）下公平对比 A / B / C，回答核心研究问题。物理指标与图像指标均须汇报，物理指标优先级高于图像指标（`00` 全局约束）。

**EXP-02: 标准主实验**

- 数据集：20,000 Train / 2,000 Val / 2,000 Test（Level 1 物理，标准退化 D2）。
- 模型：A、B、C。
- 训练：50,000~100,000 steps（最大预算），Early stopping 基于验证集总损失（空域-频域混合损失，patience 与最小步数下限见 `60` [S10]）。
- 核心汇报：
  - 图像指标：MAE、MSE、PSNR、SSIM。
  - 物理指标：$\sigma_z$、$\sigma_\delta$、$h_{\text{eff}}$、$\varepsilon_z$、$I_{\text{peak}}$ 的相对误差，以及电流剖面与能谱剖面误差；指标全集以 `70` 为准。
  - 精细结构：高频误差（DoG）、局部峰值误差。
  - 先验增益：$M_A - M_B$ 与 $M_A - M_C$。
- 判定标准：物理幻觉判定按 `70` [S4] 的操作化规则执行（样本级幻觉标志与阈值、方案级触发率与净增益聚合）；触发方案级一票否决时判定该先验形式在此条件下失效。

### Claims

- C1: EXP-02 数据集 SHALL 为 20,000 Train / 2,000 Val / 2,000 Test，物理等级 Level 1、退化等级 D2；训练/验证/测试划分 SHALL 依 `60` [S8] 的参数空间划分协议执行。
- C2: EXP-02 SHALL 在相同数据、相同空域-频域混合损失训练目标（见 `60` [S2]）、相同主干与相同训练配置下公平训练 A / B / C，训练 50,000~100,000 steps（最大预算），并以验证集总损失执行 Early stopping（见 `60` [S10]）。
- C3: EXP-02 SHALL 汇报图像指标 MAE、MSE、PSNR、SSIM 的测试集均值与标准差。
- C4: EXP-02 SHALL 汇报物理指标 $\sigma_z$、$\sigma_\delta$、$h_{\text{eff}}$、$\varepsilon_z$、$I_{\text{peak}}$ 的相对误差，以及电流剖面与能谱剖面误差；指标全集以 `70` 为准。
- C5: EXP-02 SHALL 汇报精细结构指标：高频误差（DoG）与局部峰值误差。
- C6: EXP-02 SHALL 计算并汇报先验增益 $M_A - M_B$、$M_A - M_C$ 与 $M_B - M_C$。
- C7: 物理幻觉判定 SHALL 按 `70` [S4] 的操作化规则执行；WHEN 方案级一票否决被触发，THEN 该先验形式 SHALL 被判定为在此条件下引发「物理幻觉」并失效，判定及依据 SHALL 写入总结报告。

## [S6] Phase 3: Robustness（鲁棒性消融）

Phase 3 复用 EXP-02 训练完成的模型（不重新训练），在更强退化条件下检验先验的抗干扰能力。强退化测试集由 `30` [S7] 定义的两个正交退化配置（退化强度均高于 D2）生成：EXP-03 强模糊（σ_K = 2×D2 标定值、σ_n = D2）与 EXP-04 高噪声（σ_n 尾部 SNR ≈ 1、σ_K = D2）。EXP-03/04 测试集 SHALL 为 EXP-02 测试 H（test_id ∪ test_pb，见 `60` [S8]）重退化生成：同一 H、同一划分，逐样本配对。Phase 3 完整版（每轴 ≥ 3 点分级扫描，含单调性判定）为 Should 级可选，中间点按 D2 标定值相对量定义，须满足 `30` [S8] C4。EXP-07 与 EXP-08 为例外（推理级）：两者均在标准退化（D2）的 EXP-02 测试集（test_id ∪ test_pb 全集）上冻结权重推理，其中 EXP-08 将同一测试样本集以 K=8 个独立噪声实现重新退化。迷你版 EXP-03 / EXP-04（复用 EXP-02 权重、仅推理）为强制交付（见 `90` [S6] 出口决策矩阵）；Phase 3 的完整执行仍为进阶实验。

**EXP-03: 强模糊测试**

- 数据：在强模糊测试集上直接推理，模型不重新训练。
- 目标：检验低分辨率图像丢失更多高频信息时，B 和 C 的先验能否撑住物理结构。

**EXP-04: 高噪声测试**

- 数据：在高噪声测试集上直接推理，模型不重新训练。
- 目标：检验先验在低信噪比下的抗噪能力。

**EXP-07: 先验信息量消融（推理级）**

## [S7] Phase 4: OOD Generalization（外推泛化）

Phase 4 检验网络在训练分布之外的行为：物理复杂度外推与极端参数外推。模型均不重新训练。

**EXP-05: 物理复杂度外推**

- 训练集：Level 1（无集体效应）。
- 测试集：Level 2（加入平滑 CSR/wake 扰动，由 `20` 定义）。
- 目标：检验网络是否把先验当成「死规则」。当测试集出现训练集没见过的 CSR 扭曲时，网络是盲目跟随先验（错误），还是能结合 $L$ 修正（正确）。

**EXP-06: 极端参数外推**

- 测试集：使用相对训练集采样范围上界放大 50%（双叶区间按 $|\cdot|$ 上界、两叶对称放大）的 $\beta$、$\gamma$（极端折叠；范围数值以 OQ-20-01 闭环值为准）。
- 目标：测试模型在极端物理工况下的泛化边界。

### Claims

- C1: EXP-05 SHALL 使用 Level 1 训练的模型（不重新训练），在 Level 2 测试集（含平滑 CSR/wake 扰动，由 `20` 定义）上推理。
- C2: EXP-05 SHALL 分析预测 $\hat{H}$ 对先验 $P$ 与观测 $L$ 的依赖关系，判定网络是「盲目跟随先验（错误）」还是「结合 $L$ 修正（正确）」，判定结论 SHALL 写入总结报告。

## 附录 A：失败路径选择优先级（Agent 决策规则）

当失败路径有多个选项时（典型场景：`80` [S9] G1/G2/G3 与 `80` [S11] R1–R9），Agent SHALL 按以下优先级选择失败路径并在阶段报告 [S13.3] 第 4 节记录决策依据。

### A.1 优先级排序（按从高到低）

1. **最低算力成本优先**
   - 重标定 < 重跑 < 触发新方法
   - GPU 利用率 < 80% 持续时优先调 num_workers / batch / 代码审查（与 `80` [S3] R8 处置一致）

2. **不影响三方案公平性优先**
   - 重标定 < 调整主干宽度 < 触发新方法
   - 任何引入三方案非对称调整的"换法" SHALL 升级用户

3. **不偏离原始研究问题优先**
   - 维持方法 vs 退而求其次
   - 涉及研究方向/不可变核心的"换法" SHALL 升级用户（即使看起来合理）

4. **不消耗 GPU 利用率**
   - 任何路径触发前先评估 GPU 利用率与时间预期（与 `80` [S3] 一致）

5. **不可变核心不触动**
   - 任何触动 `00` [S10] 10.1 所列条款的"换法" = 升级用户（强制介入）

### A.2 强制升级用户的触发条件

- 失败路径全部走完仍未恢复
- 算力（或 GPU 利用率）耗尽
- 触动 `00` [S10] 不可变核心
- 研究方向问题（用户拍板）

升级流程：`99` 登记 Proposed → 用户批准 → 按批准路径执行；重大需求变更走 `00` [S9] 规则 6。

### Claims

- C1: Agent 在多个失败路径可选时 SHALL 按附录 A 优先级选择，并在阶段报告 [S13.3] 第 4 节记录决策依据。
- C2: 满足 A.2 任一触发条件时 Agent SHALL 强制升级用户，SHALL NOT 静默继续。

## Decisions

### D1: 第一版只强制 Phase 1 与 Phase 2
**Chosen:** 第一版（MVP）只强制完成 Phase 1（Sanity Check）与 Phase 2（Main Experiment）；Phase 3（鲁棒性）与 Phase 4（OOD 泛化）作为后续扩展。
**Rationale:** Phase 1 与 Phase 2 直接回答核心研究问题「先验是否有效且物理正确」；Phase 3 / Phase 4 需要额外测试集构建与结果分析，成本高、不阻塞第一版交付。
**Rejected:**
- 第一版一次性完成全部四个阶段 — 实验量过大、周期过长，且 OOD 与强退化测试的结论不构成第一版交付的必需项。

### D2: EXP-02 测试集规模固定为 2,000 个样本
**Chosen:** 主实验（EXP-02）测试集固定为 2,000 个样本；测试集按 1:1 拆分为 test_id / test_pb 两子集（`60` [S8]），主判定子集 n = 1,000，统计功效由预注册扩集条款兜底。
**Rationale:** 2,000 个样本足以计算稳定的统计误差，生成与推理时间可控。
**Rejected:**
- 更小规模的测试集（如数百个样本）— 统计误差不稳定，先验增益与物理指标的结论不可靠，先验失效模式的识别不充分。

### D3: 强制输出「误差 vs 物理参数 $c_{\text{high}}$」分析图表
**Chosen:** 总结报告必须包含「误差 vs $c_{\text{high}}$（如 $\gamma$ 或 $b_1$）」散点图分析；`metrics.csv` 必须逐样本记录 $c_{\text{high}}$ 参数值以支撑该分析。
**Rationale:** 该图表是判断「网络在什么物理条件下产生幻觉」的最有力证据，可将先验失效定位到具体物理参数区间。
**Rejected:**
- 仅汇报测试集平均指标而不做逐参数分析 — 平均指标会掩盖先验在特定物理条件下的失效模式，无法回答「先验在何种工况下失效」。
