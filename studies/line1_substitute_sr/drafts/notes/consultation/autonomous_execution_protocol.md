## §0 协议定位与元规则

**无人值守的定义**：agent 全程自主运行，遇问题按本协议的限制清单（什么不能动）、偏差处理协议（出问题怎么办）、咨询协议（如何求助）、报告保障（如何交付）自行处置，最终产出符合人类研究员要求的过程、结果与报告。无人值守 ≠ 无约束自主；恰恰相反，它依赖**预先把所有不可逾越的边界与所有失败路径写死**，使 agent 在边界内无需请示。

**三支柱结构**：

1. **限制清单（§1）**——不可逾越的边界。任何自主决策前先对照 §1，触线即停。
2. **偏差处理（§2）**—问题发生时的决策树。每个失败模式都有预注册的处置路径与升级触发点。
3. **咨询 + 报告（§3/§4）**——超出自主范围时如何获得帮助、如何把结果交付成人类研究员可验收的形态。

**优先级链**（冲突时的裁定顺序）：

```
不可变核心（00 [S10] 10.1） > 冻结 spec Claims > 预注册判据与阈值
  > 本协议 > agent 默认习惯
```

**两条元规则**：

- **M-R1（先记录后行动）**：任何偏离"按 spec 字面执行"的动作，先在 `99` 登记，再执行。预授权类（00 [S14.2]）也要登记并注明"预授权类"。
- **M-R2（产物即证据）**：任何结论必须有落盘产物支撑（`metrics.csv`/`summary.json`/`stage_report.md`/咨询记录）。没有产物的"已完成"视为未完成。

## §1 研究限制清单（人类研究员视角）

从第一性原理出发：一个诚实的人类研究员开展此研究，会给自己设哪些**不可逾越**的限制？逻辑起点只有三个——(i) 结论必须回答预注册的研究问题（否则研究无效）；(ii) 结论必须可复现、可审计（否则不可信）；(iii) 结论必须忠于数据（否则是学术不端）。以下 36 条是这三个起点在五个维度上的展开。

## §2 偏差处理协议（方案出问题怎么办）

### 2.0 第一性原理：偏差初诊四问

人类研究员看到异常数据时，不会立刻动手修，而是先问四个问题。Agent SHALL 在**任何**偏差处置动作前按顺序回答这四问，并把答案写入偏差记录：

**Q1：这是测量问题，还是事实？**
> "我看到的异常，是仪器（数据管线/指标实现/评估口径）错了，还是世界（模型/数据本身）真的如此？"

- 操作：先在**已知答案的样本**上复现测量——Ĥ=H 时全部指标应取理想值（05 [S3] test_metrics 的同构检查）；L_up 直出基线的指标应可手算复核；异常指标换个独立实现重算一遍。
- 判据：若测量工具在已知答案处也错 → 测量问题（转 A/B 类）；测量工具正确而数据异常 → 事实（转 D/E 类）。
- 先例：M3 的 R_E 比率门反常（D2 > D1），初看像"网络行为异常"，实为 σ_smooth,H 抹掉分母的测量构造问题。

**Q2：这是数据问题、方法问题，还是我的预期错了？**
> 三分诊断：
> - **数据问题**：分布异常、质量不达标、泄漏、版本混用 → 查 manifest、G0 三判据、划分指纹。
> - **方法问题**：实现偏离 spec、超参不当、容量不足、数值不稳定 → 查测试、日志、梯度/输出数值。
> - **预期错了**：数据和方法都正确，只是结果不符合我的希望 → 这是**研究结果**，不是偏差（转 E 类）。注意："预期错了"不等于"我可以改预期（判据）"——判据是否可改由 §1 C 类裁定，绝大多数情况不可。

**Q3：这是孤立事件，还是系统性问题？**
> 检查局部性：单个样本？单个种子？单个方案？跨方案？跨数据版本？
- 操作：单点异常 → 样本级诊断（写入 metrics 备注）；单方案异常 → 方案实现差异排查；**多判据同时病态 → 同根归因**（M3 先例：hp 预算比/探针 ρ/R_E 比率门三条病态同根于 σ_smooth,H，一次性根因修订优于逐条打补丁）。
- 先例：Qwen agent-62 的"同根源族 vs 正交族"分诊——先确定病态是否同源，再决定是一次性报批还是分别处置。

**Q4：处置动作是否触线？**
> 拿着 §1 限制清单逐条对照拟议的处置动作：触不可变核心（A1–A7/C1）→ 停，升级用户；触预注册判据（C1–C7）→ 停，走 §2 B 类；不触线 → 按 80 附录 A 五级优先级选路并记录。

**四问的输出**：一条偏差记录（写入 `99` OQ 或阶段报告 §4），含：现象 / Q1–Q4 答案 / 分类（A–E）/ 拟走路径 / 升级判定。

#### A 类：实现缺陷（代码与 spec 不符）

- **检测信号**：L0/L1 断言失败且对应 spec 条款明确；训练 NaN/Inf；哨兵失败（Q 比 ∉[0.1,10]、Pearson ρ<0.1、val L_space 未击穿 1/N² 地板）；双空间加载断言失败；输出形状/非负异常。
- **诊断步骤**：
  1. 冻结现场：保留失败运行的完整 `results/<EXP>/` 目录（诊断证据，不删）。
  2. 代理尺度复现（≤5,000 样本、≤20,000 步；或 100 步微训练）。
  3. 定位模块：前向（形状/非负/残差基准）→ 损失（工作尺度/频带）→ 数据（字段/归一化）→ 评估（÷S 还原）。
  4. 判定"代码偏离 spec"（A 类）还是"spec 本身歧义/不可操作"（转 B 类）——判据是 spec 条款是否有唯一解读。
- **修复路径**（按 80 附录 A：最低算力成本优先）：立即修复 + 全层回归（L0+L1+smoke）；未修复禁止启动生成/训练/里程碑推进。
- **R2 特例**（全量训练发散/NaN，或 val loss 持续上升且早停未触发）：预授权流程——99 登记 → 代理尺度复现归因 → **仅实现层修复**（与 50/60 规定不符的代码偏差；禁止顺手改超参/结构）→ 全部受影响训练（默认 6 次）在同一修复后管线重跑，三方案同配置 → **全局上限 1 次**，仍失败升级 99 + 用户（不走 G2）。git 流程：`r2-fix/<日期>-<N>` 分支 + commit footer 引 99 + patch 存 `results/<EXP>/patches/`。
- **升级时点**：同一点修复 ≥3 次仍失败 → 二级咨询；R2 额度耗尽 → 用户。
- **记录要求**：99 变更明细（Type=Fixed）+ 阶段报告 §4 失败条目 + patch 文件（R2）。

#### B 类：判据不可操作（预注册判据在数据/实现上无法执行）

本项目 M1–M3 已发生 5 例（OQ-40-02/40-03/80-01/30-02/30-03），是最有本项目特色的偏差类型。

- **检测信号**：预注册判据对**所有**候选取值都失败；判据对调节旋钮不敏感（无区分度）；两条判据数学上互斥；判据分母按构造趋零（测量对象消失）。
- **诊断步骤**：
  1. 数值验证先行：派 coder 子代理写验证脚本（`scripts_tmp/consultation/<咨询编号>_<验证名>.py`，结果 `results/consultation/<编号>_<验证名>.json`），用实测数据证明"不可操作"而非"我没调对"（00 [S14.6.2]）。
  2. 区分两种子型：(i) **实现口径错**（判据语义正确、实现写错）→ 实为 A 类，修实现；(ii) **判据构造缺陷**（语义层面无法执行）→ 真 B 类。
  3. 同根归因检查（四问 Q3）：多个病态判据是否同源？同源则一次性打包修订（M3 P0 报批包先例）。
- **修复路径**：
  - 属**执行参数类**（标定判据取值、后备分支、计次口径）：99 Proposed → 按 00 [S14.2] 判断是否预授权自批准（标定采用值登记、不改判据本体的阈值落地可自批准；预注册标定判据修订需用户批准——M3 先例中 σ_smooth,H 修订走了用户批准）→ 登记注明 → 修订 → 复评 → 版本递增重生成受影响数据。
  - 属**判据本体类**（τ/触发率/λ/主指标定义）：重大需求变更流程 → **强制升级用户**，无人值守在此暂停。
- **升级时点**：B 类一律先二级咨询（Qwen）拿裁定，**不可自决**；判据本体类由咨询结论直接升级为提案呈用户。
- **记录要求**：99 OQ 七字段（ID/Question/Date/来源/Priority/Status/Resolution）+ 批准批附测试状态转化清单（99 [S5] 规则 7，清单完成前状态保持 Approved-PendingTests）+ 咨询记录（疑问/方式/判断/依据）。

#### C 类：环境问题

- **检测信号**：check_env.py 版本不符（仅警告）；GPU 不可用/被占满；磁盘满；conda 通道无锁定版本（M1 先例：matplotlib 3.9.0）。
- **处置**：环境版本不符 → 登记 99，不视为失败；GPU 缺失 → gpu 标记用例**跳过并显式标注**，不得静默通过；磁盘满 → 按 60 [S15] 15.6 生命周期清理（先删 `debug/`、过期 `test_reports/`，**不得**删实验产物与数据版本）；依赖锁定构建缺失 → 最小侵入放宽（次版本系列）+ 99 登记（M1 matplotlib 先例）。
- **升级时点**：降级处置（如双卡→单卡，80 [S3] fallback 表）可自主 + 登记；硬件彻底不可用且无法降级 → 用户。
- **记录要求**：99 登记实际环境与假设差异；单卡降级记录总时间影响。

#### D 类：门禁失败

- **G0 失败**（数据有效性）：回数据生成修正（约束联合采样/重分层/结构生成元）；硬约束——不带病进训练。涉及生成需求重大变更 → 立新 spec → 用户。
- **G1 失败**（代理尺度可行性）：先归因诊断（欠训练？捷径解？FiLM 未激活？任务太易？）——**不得跳过诊断直接宣布结论**；再三选一：修实现重跑 / 重标定退化强度重跑 / 99 backlog 触发新方法。附录 A 优先级：重标定 < 重跑 < 新方法；任务太易（R3）→ 上调 σ_K 重标定（不动 r=4，改 r 属重大变更）。
- **G2 失败**（EXP-02 全量）：按预注册分支——
  - CI 含零**且**诊断不确定（CI 半宽/方案 A 基线 >5%，或跨种子三分类不一致）→ 扩种子或扩测试集（遵守 60 [S8] 划分；**首选 EXP-08 式噪声重实现**；上限 2.0×；扩集时点预注册于 final_report）后重跑——记 99。
  - CI 含零**且**宽度达标（≤5%）→ 判"信息性等效"，按 90 等效模板报告——**禁止**解读为"无增益"。
- **G3 部分失败**：结论限定在成功子集，失败部分如实报告（不换法）。
- **G4 失败**：仅报告分布内结论，边界登记后续工作。
- **选路纪律**：多路径时按 80 附录 A 五级优先级（最低算力成本 → 不伤公平 → 不偏研究问题 → 不耗 GPU → 不触不可变核心），决策依据写入阶段报告 §4。引入三方案非对称调整的"换法"、涉及研究方向的"换法"——即使看起来合理——强制升级用户。
- **升级时点**：失败路径全部走完仍未恢复 → 用户（A.2）。
- **记录要求**：门禁判定证据（指标表/诊断输出/通过失败记录）归档于实验结果目录（80 [S9] C10）。

#### E 类：研究结果异常（先验无效/负增益/否决触发）

**这是唯一一类"正确处理 = 什么都不修"的偏差。**

- **识别**：数据（B2/B5 检查）与方法（A 类排查）都无缺陷，三分类判定为等效/显著负，或一票否决触发，或 R_E 守卫超限。
- **处置**（第一性原理：研究结果异常时，人类研究员会先问"我的预期错了吗"——答案是预期可以错，判据不能改）：
  1. **先验无效/负增益（R4）**：如实报告（10 7.2 C3）；按 90 阴性模板撰写；预注册阈值冻结；**不得**改判"无增益"为"有效"，也不得换法凑阳性。变更流程栏写明：G1/G2 + 99 + 90 阴性模板。
  2. **一票否决触发（R6）**：结论性判定，不换法；τ 与 20% 冻结；按过冲型/平滑型分类写入报告与摘要（摘要必须同时报三分类与否决判定，70 [S4] C10 优先级）。
  3. **R_E 守卫超限**：登记 99、报告标注"锐化伪影档"、发起二级咨询评估对主指标解读的影响——**不否决实验**（M3 先例：A=20.87/C=17.63 超限，B=1.15 正常）。
  4. **test_id 与 test_pb 显著分裂**：双报，结论有效域排除块邻域；不触发重新设计（90 [S6] 分支 c）。
- **升级时点**：无——E 类全程自主。唯一例外：E 类结果触发的 M6 出口决策本身属第三级（见 §5）。
- **记录要求**：99 登记（严重物理幻觉 ε_z>50% 时按 99 [S5] 规则 2 强制入 OQ）；阶段报告 §4/§5；最终报告对应章节。

## §3 Qwen 咨询协议（如何获得帮助 + 用什么思维方式）

### 3.0 咨询的总原则

- **默认可用**（00 [S14.3]）：二级咨询（更强模型/子 agent）视为默认可用，需要时直接发起，不得因担心通道不可用而推迟或降级为自主拍板；降级条款仅在通道**确实**不可用时触发（选对三方案公平性影响最小的保守选项 + 完整推理记录 + 99 登记待复核）。
- **咨询是建议，落地由主 agent 执行**（00 [S14.6]）：被咨询方不改项目文件；主 agent 收到回复后必须复核（数值自洽 / 与 spec 冲突 / 约束覆盖）才进入决策。
- **咨询不是逃避四问的手段**：先完成 §2.0 初诊四问、带着已固化的事实去咨询，而不是带着模糊的焦虑去咨询。

### 3.1 何时发起二级咨询（触发清单，00 [S14.5]）

| 场景 | 说明 |
|---|---|
| 多文档综合分析 | 不可变核心 vs 普通变更的判定；跨文档一致性矛盾 |
| 判据可操作性存疑（B 类） | 本项目最高频场景；先跑验证脚本再咨询 |
| 统计判定不确定 | CI 含零 + 诊断不确定时扩种子 vs 扩测试集的选择 |
| 代码设计权衡 | 架构/损失/超参范围（注意：已冻结项不在权衡范围） |
| 文献解读 | wang2026 论文段落精读与扩展应用（第 5 章机制分析） |
| 跨领域权衡 | 统计 + 物理 + 神经网络交叉问题 |

### 3.2 Qwen 推理思维框架（7 种，按场景选用）

给 Qwen 的 prompt 中 SHALL 显式指定所用思维框架（"请采用 X 思维分析"），并在输入包中按该框架组织材料。框架选错会让回答失焦——例如用第一性原理问一个实现 bug 是浪费，用假设检验问一个价值观问题是错位。

**框架 1：第一性原理思维**——从研究问题出发，拆解到基本事实
- 适用：判据的构造效度问题（"这个指标到底在测它声称测的东西吗"）、研究设计层面的疑问。
- 组织方式：陈述研究问题原文 → 列出从问题到判据的推理链 → 指出链条中哪一环的假设未经检验 → 请 Qwen 从基本事实重建该环。
- 项目先例：G2 掩膜语义问题——从"主指标应测 c_high 增益"出发，发现"|H_hp| 90% 能量集 = c_high 结构区域"这一假设未检验，实测 β 折叠供能 ~2.3×。σ_smooth,H=0.5× 根因修订同理（从"精细结构在 H 中可稳定分辨"的原始意图推出 0.125×）。

**框架 2：假设检验思维**——先假设 → 设计检验 → 用数据证伪/证实
- 适用：偏差归因（A/D 类）。提出互斥假设，为每个假设设计**最便宜的判别实验**。
- 组织方式：列出现象 → 给出 ≥2 个互斥假设 → 每个假设配一个判别实验（预期输出不同）→ 报告已做的实验结果 → 请 Qwen 裁定哪个假设存活。
- 项目先例：EXP-01a 输出坍缩归因（三假设：数据问题/实现问题/损失构造问题，用"500 步验证 + 输出总强度检查"判别）；坍缩修复后"字面 ρ 能否恢复"的预演修正（实测 1.90 ≫ 0.1，证伪了 Qwen 的部分预测，保留差分方案）。

**框架 3：反事实思维**——如果改 X 会怎样
- 适用：评估替换方案的成本与后果（换法的二阶效应）。
- 组织方式：明确拟议变更 X → 请 Qwen 枚举"如果执行 X，哪些下游契约/产物/判定会被牵连"→ 评估牵连面 → 决定换法还是修补。
- 项目先例：G2 分支甲（改掩膜构造为 c_high 差分能量掩膜）的反事实评估——治本但需重渲染全部产物，最终选分支乙（保留 + 披露），把分支甲留到数据重生成时机零成本推进。

**框架 4：贝叶斯更新思维**——先验 + 证据 → 后验，证据强度分级
- 适用：判定"当前证据是否足够支撑某个结论"、扩集决策。
- 组织方式：陈述待判定命题 → 当前证据及其强度（n、CI、跨种子一致性）→ 拟议新证据（扩种子/扩测试集）的预期信息增量与成本 → 请 Qwen 判断证据是否已饱和。
- 项目先例：G2 失败路径中"扩种子还是扩测试集"的选择；EXP-08 K=8 作为不确定性代理的证据强度设计。

**框架 5：临界点思维**——什么条件下结论会翻转
- 适用：敏感性分析、预注册阈值附近的结果解读、边界读法。
- 组织方式：给出当前判定 → 请 Qwen 回答"哪个量变到多少时判定翻转"（CI 宽度、种子间方差、退化强度）→ 评估当前结果离临界点的距离 → 决定结论措辞的强度。
- 项目先例：出口条件 2 的边界读法（"等效读作不反转"）；R_E 守卫值 10 的校准（EXP-01b 复评实测分布校准）；σ_smooth,P 锚点 0.55 的区间设计。

**框架 6：同根归因思维**——多个病态是否同源
- 适用：多个判据/指标同时异常时（本项目高发的模式）。
- 组织方式：列出全部病态现象 → 请 Qwen 构造"共同根因假设"→ 为根因假设设计一次性判别实验 → 若成立则一次性打包修订，反对逐条打补丁。
- 项目先例：M3 三条病态（hp 预算比 0.14 / 字面 ρ 2.75 / R_E 比率 2.58）同根于 σ_smooth,H=0.5×，一次性 P0 报批包 13 项解决；agent-62 的"同根源族 vs 正交族"分诊法。

**框架 7：测量哲学思维**——语义对齐 vs 能量对齐（00 [S3.5] 四原则）
- 适用：主指标/判据的"测什么"与"声称测什么"可能错配时。
- 组织方式：按 00 [S3.5] 四原则逐条提问——直接因果原则（主指标直接测研究问题的形式化量吗）？差分优先原则（能用差分量替代静态量吗）？成分分解披露（目标源占比多少）？先验独立可量化（泄漏占比 Π_leak）？
- 项目先例：g2_universal_redesign.md——从测量哲学层面把"修补掩膜"上升为"重新思考测量"，产出方法 A（物理量直接评估）/B（差分能量掩膜）/披露方案的通用设计。

### 3.3 咨询输入包（必带材料，00 [S14.4] 自包含要求）

被咨询方无需回读 spec 即可理解问题。输入包八要素：

1. **项目一句话定位**：FEL 纵向相空间超分研究，替代验证范式，三方案（A 无先验 / B 图像先验 / C 参数先验）公平对比。
2. **当前阶段与任务**：spec 版本（如 `v1.0+2026-08-26`）、里程碑（M4/M5/M6）、具体任务。
3. **涉及章节与 Claim**：如 `80 [S9] G2`、`70 [S7.1] C2`。
4. **当前状态快照**：关键指标数值、日志片段、产物路径（让 Qwen 能引用具体数字而非泛泛而谈）。
5. **偏差/疑问描述**：现象 + 初诊四问答案（§2.0）。
6. **已尝试的方案与失败原因**：包括"为什么不选显而易见的方案 X"。
7. **限制约束清单**：不可变核心条款、三方案公平、预注册冻结项——明确告知哪些选项在桌面上**不存在**。
8. **期望决策粒度**：选项裁定（给 A/B 选项）还是开放讨论；是否需要可执行验证脚本；是否允许修改 spec（若允许，请给出修订文字供 99 Proposed 直接采用）。

### 3.4 咨询输出验收（00 [S14.6.1]，主 agent 的复核义务）

收到回复后逐项验收，不合格则返回补充咨询（说明缺口）：

| 验收项 | 要求 |
|---|---|
| 结论先行 | 推荐方案 + 一句话理由在回复开头 |
| 结构完整 | 推荐方案 / 备选方案（含否决理由）/ 依据 / 影响（公平性/研究目标/预注册纪律/算力）/ 修订文字（如需改 spec） |
| 验证义务 | 涉及数值、判据可操作性、统计口径的判断必须附可执行脚本或完整推导；有执行能力时应直接跑验证附结果 |
| 只读约束 | 被咨询方不改 `src/`/`tests/`/`docs/specs/`/`config.yaml.template`；验证脚本限 `scripts_tmp/consultation/`、结果限 `results/consultation/`（命名 `<咨询编号>_<验证名>.{py,json}`） |
| 验收移交 | 主 agent 复核三项：数值自洽性、与 spec 冲突检查、约束覆盖检查 |
