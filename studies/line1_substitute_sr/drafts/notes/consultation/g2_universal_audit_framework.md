**文本草案**：

> **§[S15] 流程漏洞审计方法论（研究治理基础设施）**
>

### F2：主指标语义对齐原则（测量哲学）

**来源**：主 agent G2 通用型方案的核心原则——"主指标 = f(研究问题的形式化) ≠ f(最容易计算的代理量)"。

**通用性论证**：任何用"代理量"作"主指标"的研究都面临"测错对象"风险（如本项目的 |H_hp| 能量 ≠ c_high 精细结构）。**这是测量哲学层**——比本项目 G2 修复更普适。

**补入位置**：`00_master_spec.md` 新增 [S3.5] 测量原则 + `70_evaluation_spec.md` [S7.1] C1 修订"主指标构造原则"。

**文本草案**：

> **§[S3.5] 主指标语义对齐原则**（研究方法论基础）
>
> **§[S3.5.1] 原则陈述**：
> 1. **直接因果原则**——主指标 SHOULD 直接测量研究问题形式化的物理量，而非"最容易计算的代理量"。例：研究"c_high 精细结构恢复" → 主指标直接基于 c_high 引起的差异（参数差分），而非基于 H 高频能量（c_high + c_mid + 噪声的混合）
> 2. **差分/敏感度优先**——任何"基于静态量（如 |H| 能量）"的判据 SHOULD 优先改为"基于差分/敏感度（如 |H − H_¬ch|）"——前者是混合源的混合表征，后者是目标源的直接提取
> 3. **成分分解强制披露**——任何"基于某类源能量/特征"的判据，报告 MUST 同步给出"源成分分解"（如 c_high 占比 / c_mid 占比 / 其余占比），让读者能评估主指标"测的是不是它声称测的"
> 4. **先验独立性可量化校验**——任何"先验 X 不暴露信息 Y"声称，报告 MUST 给出"先验 X 携带 Y 信息的占比"（如先验泄漏指数），字面校验 ≠ 物理性校验

**§[S3.5.2] 适用**：
> - 主评估指标（70 [S7.1]）
> - 门禁判据（80 [S9] G0-G4）
> - 一票否决判定（70 [S4]）
> - 任何"测什么"与"声称测什么"可能错配的指标

**§[S3.5.3] 例外与边界**：
> - 代理量在"直接因果不可得"或"计算不可承受"时可用——但 MUST 显式说明"为何用代理"与"代理的已知偏差"
> - 成分分解在"源不可分离"时退化为"已知源占比 + 未知残差"

**与 70 [S7.1] C1 修订协同**：70 [S7.1] C1 应补"主指标构造须遵循 [S3.5] 原则"。

**实施成本**：低（spec 文本 + 70 C1 补注）| 不影响 P0

**通用性论证**：任何"训练用尺度 X、评估用尺度 Y"的方案都面临"X 与 Y 的转换契约"问题（不仅是本项目坍缩修复引入的工作尺度——许多 SR/超分/多尺度项目都有）。**契约缺失会导致静默错误**。

**文本草案**（合并三处）：

> **§双空间契约约定**（任何含尺度变换的方案通用）
>
> 1. **空间显式标注**——任何"输出张量" MUST 在 docstring/类型提示/字段名中标注"所在空间"（如"工作尺度"vs"Σ=1 评估空间"）；模型 forward 返回值、checkpoint state、metrics 字段值、日志记录值 MUST 显式标注
> 2. **转换点显式**——所有空间转换点（×S、÷S、log、softmax）MUST 在代码注释中说明"输入空间 → 输出空间"与"为什么需要这个转换"

### F5："基于能量/边缘"判据的成分分解强制披露原则

**来源**：Qwen P2/G2/E2（掩膜能量/峰值主要选 β 折叠而非 c_high；P2 携带 c_high 泄漏）。

**通用性论证**：任何"基于某类源（c_high / c_mid / 其他）的能量/特征"的判据都面临"主指标主要测的是哪个源"的问题。**诚实呈现必须要求成分分解**——与"主指标对齐研究目标"互为表里（F2 是哲学，F5 是执行）。

**补入位置**：`70_evaluation_spec.md` 通用方法论（可加在 [S3.5] 或 [S5] 后）。

**文本草案**：

> **§主指标的成分分解强制披露**（70 evaluation 通用）
>
> 1. **适用范围**——任何"基于某类特征 X 的能量/形态/位置"的主评估指标或门禁判据，报告 MUST 同步给出"X 占比分解"（哪些是 X 实际贡献、哪些是其他源贡献）
> 2. **分解方法**——"差分能量法"（H − H_X_removed，X_removed = 该类源清零版）+ "对照法"（原指标 + 各源置零后指标，差即贡献）
> 3. **披露格式**——表格 + 阈值警告（如"X 占比 < 30% → 判据可能失真"）
> 4. **影响等级**——若分解显示主指标主要测的是非目标源（如本项目"主指标 47% 来自 c_high，但 109% 来自 β"），报告 MUST 显式标注"主指标对目标源不盲但结构性偏倚"——并讨论这是否影响研究结论

**实施成本**：中（评估函数 + 报告字段 + 测试）| Qwen 提案 2 已含（E2 提案 18 待 M5）

### F6：生成前可行性校验原则（任何参数选参实验）

**来源**：Qwen D4/D2 提案 15（EXP-04 σ_n 选参生成前校验）。

**通用性论证**：任何"先选参后生成"或"先标定后跑"的实验都面临"参数选错导致整个实验失败"问题。**生成前校验把"事后发现"提前到"事前拦截"**——任何选参/标定类实验都适用。

**补入位置**：`80_experiment_matrix.md` [S9] 通用方法论 + `30_degradation_spec.md` C7 附注。

**文本草案**：

> **§生成前可行性校验原则**（任何含参数选参的实验通用）
>
> 1. **触发**——任何实验在生成数据/开始训练前，SHALL 跑"生成前可行性校验"脚本：验证关键判据（如 SNR_hf、SNR_main、判据门槛）在生成参数下不冲突
> 2. **关键判据 vs 选参的因果关系**——脚本 SHALL 列出"该参数 → 该判据"的数学关系（如 σ_n ↑ → SNR_main ↓、SNR_tail ↓；σ_K ↑ → R_E 收敛；C₀ ↑ → 显存 ↑、step_time ↑）
> 3. **不通过处置**——若生成前校验不通过，SHALL 调整参数到满足为止（不调整判据——避免"为了让判据通过而调判据"的事后偏袒）
> 4. **登记**——参数选定的实际值（含偏离"理论值"的部分）SHALL 登记在 config.yaml + 99 笔记
> 5. **可复现**——校验脚本 SHALL 与实验代码同仓库，不依赖外部工具

**实施成本**：低（脚本 + 文本）| Qwen 提案 15 + 提案 11 部分覆盖
