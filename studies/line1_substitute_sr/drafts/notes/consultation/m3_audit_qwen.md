#### G1 — σ_smooth,H 按构造抹杀高频（根因条目，已登记 OQ-20-03）

- **隐藏假设**：渲染平滑核只影响「数值稳定可分辨」（20 [S3] C4 意图），不影响任何以 H 高频为参照/分母的判据。
- **失真证据**：0.5×w_fine 时高斯传递函数在精细结构尺度 T≈0.0072，实测 ‖H_hp‖₁/ΣH 仅 0.017%；OQ-40-03 hp 预算比恒 ≈0.14、OQ-80-01 字面 ρ 恒 ≈2.75、OQ-30-03 R_E(D2)/R_E(D1)=2.58 反常——三条独立病态同根（99 2026-08-26 综合裁定）。
- **优先级**：P0（报批包第 1 项：σ_smooth,H=0.125×w_fine 逐样本，能量保留 exp(−π²/16)≈54%，预演实测高频能量提升 3.8 倍）。
- **影响范围**：20 [S3] C4 文本 → dev1/v1 版本递增重生成 → G0 复评 → EXP-01 标定重跑 → 四个高频判据复验；M4–M6 全部训练/评估数据底座。

#### G2 — 主指标掩膜语义（核心新发现，未登记）

> **这是本轮审计最重要的发现。它不是判据数值病态，而是主指标的构造效度（construct validity）问题：M4 的主判定可能根本没有在测 c_high 增益。**

- **隐藏假设**：70 [S7.1] 预注册主指标 $\mathcal{E}_{\text{high}}^{\text{mask}}$ 的掩膜 $M_{c_{\text{high}}}$ 定义为「|H_hp| 幅值降序取累计能量达 90% 的最小像素集」，并**宣称**这是「$c_{\text{high}}=\{a_3,\gamma,b_1\}$ 所控精细结构（三阶 S 形、精细卷曲、局部厚度变化）所在区域的空间掩膜」（70 spec 第 228 行原文）。该定义把**两个不同的集合用等号连接**：
  - 集合 A（操作性定义）：|H_hp| 90% L1 能量像素集——**纯能量排序，不认结构来源**；
  - 集合 B（语义宣称）：c_high 参数所控结构的空间支撑区域。
  两者仅在「c_high 结构贡献 H 高频能量的绝大多数」时近似相等。
- **失真证据**（σ_smooth,H 修订为 0.125× 后该假设反而更脆弱）：
  1. 旧口径 0.5× 下 H 高频几乎全灭，掩膜选谁都差不多，语义失真被掩盖；0.125× 把高频能量释放出来（×3.8），**谁贡献高频谁被选中**，语义问题显形。
  2. 参数结构：β∈**c_mid**（20 [S8] C1：c_mid={a₂,β}，c_high={a₃,γ,b₁}），采样下界 |β|≥0.9 保证主折叠存在（20 [S9] β 行），自洽示例 β=1.2、σ_smooth,P≈1.1px 时折叠边缘在频带 f_c=1/8 的传递 T(f_c)≈0.69——**β 折叠是 0.125× 口径下 H 高频能量的主要供体**。a₃/γ 幅度低一个量级（|γ|≤0.6 且受 βγ<0 约束）、b₁ 是缓变厚度调制，三者的频带能量份额可能远低于 90%。
  3. 后果：**掩膜可能主要选中 β 折叠边缘而非 c_high 结构**。P2 先验的构造包含 β 折叠（P2 由 c 的低阶观测量构造，折叠位置由 (a₁,α,β) 决定，20 [S5] C2），因此方案 B 在参数级不泄漏 c_high（`test_c_high_invariance` 只证明参数级不变性），却在**主指标的能量区域里结构性占优**——B 的「先验增益」可能测到的是「先验携带折叠信息」而非「先验帮助恢复 c_high」。
  4. 70 [S7.1] C2 只约束「掩膜不依赖方案输出、三方案同一掩膜」——这是**公平性**条件，不是**效度**条件。掩膜对三方案公平，不等于掩膜测的是预注册想测的量。
- **优先级**：**P0（条件性）**——由脚本 a（`scripts_tmp/g2_c_high_leak.py`）实测裁决：掩膜内 c_high 差分能量占比中位数 **<40% → 坐实，升为无条件 P0**，70 [S7.1] 掩膜构造必须在 EXP-02 前修订；**≥40% → 降 P1**，仅登记效度说明条款 + 在 final_report 报告掩膜能量成分分解。
- **影响范围**：70 [S7.1]（掩膜定义）、80 [S9] G 门禁（主指标解读）、90 [S6] C2 条件 1（「显著正增益」的归因）、M4 主判定、M6 结论命题 (b)。
- **与 G1 的关系**：G1 修复是 G2 显形的**前提**——两漏洞耦合，批准顺序上 G1 先行、G2 验证紧随（§5 路径图）。

  1. **锐化倾向与根因修复正交**：R_E 病态有两个成因——(i) 分母脆弱（G1 修复解决，×3.8）；(ii) 分子过冲（L1 驱动 + 长训练的锐化过度，EXP-01a 实测 A=78/B=35/C=389，5,000 步短训）。EXP-02 是 50,000–100,000 步，**训练时长 ×10–20，分子过冲没有任何机制保证不回潮**，而原门只在标定期（EXP-01b，短训）定义，EXP-02 期间 R_E 无判据管辖。
  2. **后备分支的场景限定**：OQ-30-03 后备只覆盖「σ_K 标定」场景，不覆盖「主实验训练中 R_E 病态」。
- **建议**（§3 提案 12）：在 80 [S4] C3 或 [S9] 增补——EXP-02 评估期计算 R_E 三方案中位数，预注册上限（建议 10，即输出高频能量 ≤10× 真值；依据：EXP-01a 5,000 步已达 35–389，但那是分母脆弱口径下的值，0.125× 口径下需 EXP-01b 复评后重定——**因此上限本身也应预注册为「复评后登记，EXP-02 前定死」**），超上限不否决实验、触发诊断评估（登记 99 + 二级咨询）。这样失效路径存在但不破坏预注册纪律。

### 2.8 第 8 项（σ_smooth,P 预授权扩展）：现文本对 M5 不合理，需澄清

40 [S5] C5 现行文本：「若候选值扫描后无法落入 [0.5,0.95]，SHALL 扩展候选集**一次**（需 99 登记并批准）」。

- **M5 EXP-03/04 强退化下是否仍合理？——现文本下不合理，两种失败模式：**
  1. **字面失效**：「一次」若解读为全生命周期一次，则 M3 EXP-01d 标定若已用掉扩展（预演显示初始中心 2σ_smooth,H 在旧口径下批量均值 ≈0.17 低于下界，扩展路径是现实可能），M5 任何场景都没有第二次机会——即使强退化下出现了全新的谱结构证据。
  2. **语义缺位**：σ_smooth,P 是**先验构造参数**，跨退化档冻结（公平性）；强退化下质量门漂移的正确处置大概率**不是**扩展候选集重选（那会让 B/C 先验在强退化档单独优化，破坏三方案同先验的公平），而是**接受漂移并记录**——现文本没有「接受并记录」这个出口，只有「扩展一次 → 仍不满足取最接近值并记录」。
- **建议**（§3 提案 7）：澄清为——「一次扩展」按「每次 σ_smooth,H 修订批 + 每次标定里程碑」计次；**M5 强退化档下质量门漂移不触发重标定**，仅登记诊断；确需在强退化档重选 σ_smooth,P 的，属研究方向级变更，强制升级用户（00 [S14] C5）。
- **适用性结论：第 8 项按现文本报批会在 M5 留下死路；建议报批时即采用澄清文本（修订成本为零，因为尚未批准）。**

## §4 三个可执行验证脚本（已写入 `scripts_tmp/`，均已冒烟通过）

> 三个脚本只用 **stdlib + numpy + scipy + 已安装的 `src/*`**，无新增依赖、不需要 torch（当前环境 torch 动态库存在加载问题，脚本刻意绕开；训练流程不受此影响，EXP-01a 已实测可训）。批准后的正式运行由主 agent 执行，脚本留在 `scripts_tmp/`，用后清理。

### 4.1 脚本 a：`scripts_tmp/g2_c_high_leak.py` — G2 验证（决定 P0/P1）

- **目的**：检验 70 [S7.1] 掩膜 $M_{c_{\text{high}}}$（|H_hp| 90% 能量像素集）在 σ_smooth,H=0.125×w_fine 下是否真的选中 c_high={a₃,γ,b₁} 结构。方法：差分能量法——渲染完整 H、c_high 清零版 H_noch（a₃=γ=b₁=0）、β 清零版 H_nob（β=0），计算掩膜内「c_high 移除敏感度」= Σ_M|H_hp−H_noch_hp|/Σ_M|H_hp| 与 β 对应量。
- **依赖**：numpy/scipy + `src.generators`（sampling/f_beam/masks）。
- **用法**：
  ```bash
  python scripts_tmp/g2_c_high_leak.py --n 30            # 正式运行（≈10 s 渲染 + 导入）
  python scripts_tmp/g2_c_high_leak.py --n 30 --compare-old   # 附旧口径 0.5× 对照
  ```
- **预期输出表**：逐样本 `idx | beta | w_fine_px | mask_px% | ch_in_mask | b_in_mask | ch_full | b_full` + 中位数行 + `VERDICT` 行。
- **解读规则**：
  - `ch_in_mask` 中位数 **< 0.40** → G2 坐实 → **升无条件 P0**，按提案 2 分支甲修订 70 [S7.1]（掩膜改为 c_high 差分能量掩膜，原掩膜作对照双报）。
  - **≥ 0.40** → **降 P1**，按提案 2 分支乙：保留定义 + 强制登记掩膜能量成分分解表与效度声明。
  - `b_in_mask` 为敏感度读数（差分非正交分解，可 >1.0，脚本 docstring 已注明）；持续 ≫ `ch_in_mask` 时即使走分支乙，主指标归因说明也必须显式写明「对 β 折叠非盲」。
- **本轮冒烟实测（n=30，0.125× 口径，审计种子 9999，非正式裁决）**：中位数 `ch_in_mask=0.453`（分布宽，0.17–0.78，约 1/3 样本 <0.40）、`b_in_mask=1.087`、`mask_px%=50%` 左右。按预定阈值落入分支乙，但 β 敏感度 ≈2.4× c_high 敏感度，属**边界情形**——正式裁决由主 agent 在批准后重跑（建议 n≥30，可同时 `--compare-old` 留对照证据）。无论落入哪支，提案 2 的成分分解披露都应执行。

### 4.2 脚本 b：`scripts_tmp/dual_space_audit.py` — 双空间契约扫描

- **目的**：静态扫描 `src/` 全部代码，检测工作尺度（×S=65536）与 Σ=1 空间边界的任何失配——模型输出忘了 ÷S、损失目标忘了 ×S、checkpoint 未持久化/未校验 work_scale、日志混记两个空间。对应漏洞 N2/T3，服务于提案 8/9/19。
- **依赖**：仅 stdlib（ast + re），任何环境可跑。
- **用法**：`python scripts_tmp/dual_space_audit.py`（退出码 0 = 无 P0 级失配）。
- **检查项**：C1 forward_scheme 输出配对（÷S 或 ×S 同空间）/ C2 训练侧 `batch["H"]` 目标配对 / C3a checkpoint 保存含 work_scale / C3b 加载侧一致性断言 / C4 日志空间标注 / C5 infer 还原回归哨兵。
- **解读规则**：C1/C2 FAIL = **P0**（EXP-02 前必修）；C3b/C4 FAIL = P1（提案 9/19）；C5 FAIL = 数据损坏风险。
- **本轮实测结果**：`n_fail_p0=0`、`n_fail_p1=4`——C3b FAIL（`evaluate.py` load_model 无 work_scale 断言，即漏洞 N2 坐实）+ C4 FAIL×3（`train.py:384-386` out_min/out_max/out_sum 工作尺度无标注，即漏洞 T3 坐实）。其余 PASS（含 C5 还原哨兵）。**结论：当前实现无 P0 级空间错误，两处已知 P1 缺口与报告一致；建议本脚本进 M4 前必跑清单（每次 checkpoint 相关代码变更后复跑）。**

### 4.3 脚本 c：`scripts_tmp/exp04_snr_main.py` — EXP-04 SNR_main 校验

- **目的**：验证 30 [S7] C7 硬下限（主束区域 $\text{SNR}_{\text{main}} = \text{mean}_M(L_{clean})/\sigma_n \ge 2$）在 EXP-04 档（σ_n 调至尾部区域信噪比 ≈1）下是否仍成立。关键恒等式：$\text{SNR}_{\text{main}}/\text{SNR}_{\text{tail}} = \text{mean}_M/\text{mean}_T$ **与 σ_n 无关**，故可行性可在生成前判定（漏洞 D2 的生成前拦截实现，提案 15）。
- **依赖**：numpy/scipy + `src.generators`。
- **用法**：
  ```bash
  python scripts_tmp/exp04_snr_main.py --n 8                 # 当前 v1 口径（0.5×）
  python scripts_tmp/exp04_snr_main.py --n 8 --factor 0.125  # 批准后按 v2 口径复算
  ```
- **预期输出表**：逐样本 `snr_tail(cur) | snr_main(cur) | snr_full(cur) | ratio_M/T` + 中位数 + EXP-04 档外推 + `VERDICT`。
- **解读规则**：`snr_full(cur)` 应 ≈2（复核 σ_n=1.22e-4 的全图均值口径标定，OQ-30-02）；EXP-04 档 `SNR_main` 中位数 ≥2 → C7 可行；<2 → 按提案 15 回退 σ_n（尾部目标改为 2/ratio，偏离值登记 99）。
- **本轮冒烟实测（n=4，σ_K=11.0，审计种子 8888）**：`snr_full=2.00`（标定口径复核通过）、`ratio_M/T` 中位数 **105.8**、EXP-04 档 SNR_main ≈106 ≫ 2。**结论：EXP-04 的 C7 硬下限以约 50 倍裕度满足**——σ_n 上调至尾部 ≈1 时任务仍保持超分而非去噪；M5 无需修订 EXP-04 定义，生成前复跑一次本脚本存档即可。

### 5.3 流程漏洞审计方法论（可复用，每阶段执行）

每个里程碑完成后、进入下一阶段前，执行 30–60 分钟结构化审计：

1. **清单来源（三源合并）**：
   - 上次审计遗留项（本报告 23 条清单为 M3 基线）；
   - 本阶段实施中新暴露的异常（B 类登记、xfail、运行时怪象、日志口径疑问）；
   - 重读本阶段新写/修订的 spec 文本（含 99 新批次）——**只读本轮变更的 diff，不重读全文**，控制时长。
2. **逐条过四问**（本报告 §1 的固定格式）：隐藏假设是什么 → 失真证据在哪（必须给 file:line / 实测数 / spec 条款，不接受纯叙述）→ 优先级（P0–P3 按 §1 标度）→ 影响范围（哪些里程碑消费）。
3. **输出**：新发现登记 99（OQ 或变更条目）+ 新修订建议按 P0/P1/P2/P3 分组（格式同 §3）+ 更新后的清单总数。
4. **阻塞规则**：**仅 P0 阻塞下一阶段**；P1 记入「下阶段启动前」清单；P2/P3 入 backlog。审计本身 ≤1 小时，超时即停、遗留转下次——审计不能变成项目。
5. **与脚本配套**：脚本 b（双空间）在每次触碰 checkpoint/损失/日志代码后复跑；脚本 a 在每次触碰掩膜/频带实现后复跑；脚本 c 在每次退化参数变更后复跑。
